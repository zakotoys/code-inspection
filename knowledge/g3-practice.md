## 推荐体验：全部在开发宿主中操作

1. 在原窗口停止旧 F5 调试，再按 F5，确保加载本次编译后的扩展。
2. 在新开发宿主中执行 `Code Inspection: 启动 MCP 服务`。
3. 执行 `Code Inspection: 通过 MCP 查询当前诊断`。
4. 输出面板应显示“通过本机 HTTP / MCP 查询成功”、工具名称和 JSON。这个结果是一次查询结果，不会自动刷新。
5. 修改 sample.ts 制造类型错误，等待语言服务显示错误，再执行查询命令。
6. 修复后再次查询，确认对应错误被移除。也可启用 Python 诊断插件后用 sample.py 体验。
7. 停止服务，再执行查询命令，应提示先启动服务。

该命令实际创建官方 MCP Client，经 HTTP 调用服务端，避免剪贴板与终端影响体验。独立终端脚本仍可用于验证另一个进程的连接。

## 终端查询：注意剪贴板顺序

先把下面的命令输入到终端，先不要回车；再去开发宿主执行“复制 MCP 配置”；回到终端直接按回车，不要再次复制命令。

```powershell
Get-Clipboard -Raw | npm run mcp:inspect
```

复制命令会覆盖刚刚复制的 JSON 配置。服务重启后，旧配置也会失效。输出里若已经出现 `node scripts/inspect-mcp.cjs`，说明 npm 已找到脚本；不能仅凭终端位于 fixture 目录就认定路径错误。仍推荐在仓库根目录运行，便于理解上下文。

## 错误提示怎么看

| 前缀 | 意义 | 下一步 |
| --- | --- | --- |
| INPUT | 没收到输入或直接交互运行 | 复制配置并正确通过 stdin 传入 |
| CONFIG | 非 JSON、结构/地址/令牌格式不符合要求 | 重新复制配置；避免随后复制别的文本 |
| CONNECT | 本机地址连不上或超时 | 保持开发宿主开启；启动服务，重新复制 |
| AUTH | HTTP 401，令牌失效或不正确 | 使用本次启动的配置 |
| ENDPOINT | 响应不像当前 MCP 地址 | 重新启动并复制地址配置 |
| PROTOCOL / TOOL | 协议连接或工具调用失败 | 重启重试，并报告错误前缀；不要发送令牌 |

终端脚本先做有超时的本机连通/认证检查，再使用 SDK 发现和调用工具。固定的错误提示不回显输入或底层任意异常，避免把包含令牌的配置打印到日志。
