# G6：暂停、恢复与重载

更新：2026-09-12。实现与自动验证通过，用户体验待确认。

## 1. 三种状态不能混在一起

| 状态 | 意义 |
| --- | --- |
| state:ready | 保存观测正在运行，不代表项目没有错误 |
| state:paused | 不产生新的保存批次，但本地当前诊断继续更新 |
| state:unsupported | 当前不是支持的本地桌面环境，diagnosticsEnabled:false，并给出 unsupportedReason |
| mcpEnabled | 单独表示 MCP HTTP 服务是否运行，与暂停和错误数无关 |

get_detector_status 返回这些状态；get_save_batches 额外返回 detectorState。当前诊断为空、暂停、服务停止分别是三件事。

## 2. 暂停时做了什么

执行 `Code Inspection: 暂停保存观测`：

1. 取消所有待定观测和计时器，不再等它们完成，也不追加“暂停导致失效”的历史任务。
2. 清空旧历史、最近批次与比较基线，更换历史 sessionId。
3. 暂停期间保存不会创建待定批次；诊断事件仍更新 G2 当前快照。
4. MCP 若已启动，继续运行，可以查询状态和当前诊断。持有旧历史身份的客户端会收到 SESSION_CHANGED。

选择清空旧历史，是为了避免暂停后下游仍从本服务拿到先前待处理的提醒。它不能撤回客户端已经读走的数据，消费端仍必须在执行前复核当前状态。

重复暂停是幂等的：不会反复更换会话、制造记录。这里的幂等就是“同样操作做两遍，不产生两份额外效果”。

## 3. 恢复与基线

执行 `Code Inspection: 恢复保存观测` 后，开启新历史会话。每个文件下一次成功保存观测重新建立 baseline，已有诊断保留但 added 为空。暂停期间出现过什么不会补发。

这意味着恢复时已有错误不会立刻记为新增提醒。恢复后用户继续保存、诊断发生变化，才与新的基线比较。当前快照查询随时仍能显示这些已有错误。

## 4. 重载规则

暂停是当前扩展实例的内存状态，不写入文件或设置。重新加载窗口、重启开发宿主或编辑器后，扩展激活时默认 ready，历史与基线从空开始。不会回放上一次运行的旧问题；如果需要继续暂停，应再次执行暂停命令。

实现过程中尝试过工作区存储持久化暂停，但真实测试宿主快速退出时下一实例未读到预期状态。G6 原目标不要求跨重启持久化，所以移除了该路径，采用明确、统一的实例内语义；没有留下备用存储或兼容逻辑。

退出时关闭 MCP 监听和连接，清理诊断事件订阅与待定观测计时器。停止 MCP 命令只关闭服务，不等于暂停保存观测。

## 5. 支持环境

当前支持本地桌面 VS Code 的 file 工作区。远程 SSH、WSL、容器场景的状态逻辑返回 unsupported / remote，并拒绝启动 MCP。浏览器环境判断返回 unsupported / web；交付包不声明 browser 入口，因此 Web 版 VS Code 通常会直接显示扩展不可用，不应期待它执行 Node.js 服务。

包声明 workspace 扩展类型与不支持虚拟工作区；不受信任工作区仅允许本地诊断，启动 MCP 仍要求工作区受信任。本轮只有本地 Windows 的真实运行证据，环境判断使用单元测试验证，没有运行真实远程或浏览器宿主。

## 6. 亲自体验

1. 重新 F5，启动 MCP，产生并读取几份保存批次。
2. 执行“暂停保存观测”，再执行“查看检测器状态”，应显示 paused，MCP 仍可为已启动。
3. 修改 sample.ts 制造错误，执行“通过 MCP 查询当前诊断”，仍能看到错误；保存后观察 pending 为空、历史没有新批次。
4. 继续用暂停前的读取位置续读，应看到 SESSION_CHANGED。重置读取位置后返回空历史与 paused 状态。
5. 执行“恢复保存观测”，在仍有错误的文件中作实际修改并保存，等待观测。应看到 baseline:true、added:[]，诊断正文仍保留已有问题。
6. 修复并保存后，后续批次能看到变化。
7. 暂停后重启 F5，再查看状态，应是 ready，历史为空。此步骤验证的是明确的新实例行为。

## 7. 代码和验证

src/save-observations.ts 的 setPaused 负责清理并切换采集状态；src/vscode-source.ts 分开维护当前诊断与保存观测；src/environment.ts 负责环境判断；src/extension.ts 注册暂停/恢复命令；src/mcp.ts 返回运行状态。

单元测试验证暂停时取消计时、停止追加、幂等、恢复基线及不支持环境原因。真实宿主验证暂停期间诊断继续更新、保存不产批次、恢复首次保存为基线以及重启默认 ready。开发模式和安装包模式都验证了退出端口关闭。完整证据见 G6/G7 验证记录。
