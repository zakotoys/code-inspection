## 已打通的链路

VS Code 诊断 → 当前快照 → 保存观测 → 有界历史 → MCP 当前/历史查询 → 标准客户端。

安装 VSIX 后也能执行同一链路。暂停/恢复、缓存缺口、会话变化、超大正文省略都有明确可观察行为。当前没有自动轮询模型或发送设备指令。

## G8 需要队友明确或参与的事项

1. 实际使用哪个 Agent 宿主、如何填写本机 HTTP 连接和 Authorization 请求头；是否与扩展运行在同一机器。
2. 谁负责轮询/调度，何时读取 get_save_batches，以及如何保存每个消费端的历史 sessionId/nextCursor。
3. 如何按 batchId 识别重读，处理 RESYNC_REQUIRED、baseline、invalidated、payloadOmitted 和暂停状态。
4. 执行提醒前怎样查询当前诊断，避免对已经修好的历史问题反馈。
5. 先以日志或普通通知复现“保存错误 → 消费端读到 → 修复 → 读到变化”；重复读取不能成为重复任务。

这些是具体联调输入，不要求先完整实现所有设备功能。模型选择、双 Agent 分工和设备参数由对应模块负责。
